## 5. 되살리는 차례

> 🔴 **처음 할 때는 반드시 빈 연습용 프로젝트에서 하세요.** 운영에 바로 하지 마세요.
> 연습용 프로젝트는 **메일·알림을 내보내는 쪽(Cloudflare Functions·cron)과 끊어 두고**
> 시작합니다. 안 끊으면 자료를 넣는 동안 **직원들에게 알림이 쏟아집니다.**

### ① 내보내는 쪽부터 끊습니다 — DB 가 아니라 **바깥**에서

`data.sql` 이 `push_config` 를 **통째로 되살립니다.** 그러니 "복구 전에 URL 만 비우기"는
**안전하지 않습니다.** 넣고 나면 다시 채워집니다.

끊어야 할 것:

- Cloudflare Pages 의 `/api/notify` · `/api/mail-check` 가 **그 DB 를 보지 못하게** 합니다
  (연습용이면 애초에 연결하지 않습니다)
- Supabase 의 **pg_cron 일정**을 멈춥니다 — `viren-mail-check` · `viren-push-log` 등

```sql
-- 넣기 전에 (연습용 프로젝트에서)
select cron.unschedule(jobname) from cron.job;
```

### ② 암호화를 풉니다
```bash
7z x viren-work-2026-11.7z
```

### ③ roles → schema → data — **한 번에, 한 덩어리로**

```bash
psql "<연결 주소>" --single-transaction --variable ON_ERROR_STOP=1 -f roles.sql -f schema.sql -c 'SET session_replication_role = replica' -f data.sql
```

**끝난 값을 꼭 확인하세요. 셸마다 보는 법이 다릅니다.**

```bash
echo $?
```

윈도 PowerShell 이면 이쪽입니다.

```bash
$LASTEXITCODE
```

> 🔴 **한 psql 호출에 몰아넣습니다.** 세 번 나눠 부르면 **셋이 따로 도는 것**이라,
> 가운데서 걸렸을 때 앞의 것이 남아 반쪽이 됩니다.
>
> · `--single-transaction` — 중간에 걸리면 **통째로 되돌립니다.**
> · `ON_ERROR_STOP=1` — 첫 오류에서 **멈춥니다.** 없으면 오류를 지나치며 계속합니다.
> · `SET session_replication_role = replica` — 자료를 넣는 동안 **방아쇠를 끕니다.**
>   안 끄면 넣을 때마다 알림이 나가고 목록 갱신이 뒤틀립니다.
>
> ⚠️ **0 이 아니라고 해서 "아무것도 안 들어갔다" 고 단정하지 마세요.**
> `--single-transaction` 은 오류가 나면 되돌리지만, **연결이 끊기거나 창이 꺼진 경우**
> 끝난 값만으로는 알 수 없습니다. 커밋 **직후**에 끊겼을 수도 있습니다.
>
> 🔴 **되돌아갔는지 확인하기 전에는 다시 돌리지 마세요.** 확인할 것:
> · psql 이 찍은 글(마지막 줄에 `COMMIT` 이 있었나)
> · 대상 DB 의 실제 건수 — `select count(*) from public.employees;` 처럼 몇 개만 세어 봅니다
> 확인이 안 되면 **담당에게 알리고 멈추세요.** 모르는 채로 다시 돌리면 반쯤 들어간 위에
> 또 덮어씁니다.
>
> 역할 관련 오류(`cli_login_postgres` 등)가 나면 **그 오류와 대상을 그대로 담당에게
> 알리세요.** 역할을 지우는 것은 영향이 큰 일이라, 무엇을 지울지는 **사람이 판단**합니다.

### ⑥ 🔴 알림은 **아직 켜지 않습니다**

되살린 `mail_state` · `user_mail` 에는 **그때까지 어디까지 봤는지**가 들어 있습니다.
그 뒤로 온 메일은 전부 **새 메일로 보입니다.**

**사서함마다** `uidvalidity` 와 `last_uid` 가 따로 있고, 지금 메일함의 실제 위치는

> ⚠️ **사서함별 실제 상태를 확인하기 전까지 알림을 켜지 마세요.**
> 확인 없이 켜면 지난 메일이 한꺼번에 쏟아집니다.
> 어떻게 맞출지는 **담당이 메일함을 보고 판단**합니다 — 여기 적어 둘 수 있는
> 한 줄짜리 SQL 은 없습니다.

`push_subs`(기기 등록)도 옛 등록이 되살아납니다. 지운 앱으로 계속 쏘게 되니,
비우고 직원들이 다시 켜게 하는 편이 깨끗합니다.

### ⑦ 확인 (8번 목록)을 **다 지난 뒤에** 내보내는 쪽을 다시 잇습니다

---

### 전체 dump 가 없고 2번 꾸러미만 있을 때

업무 자료 13개 표만 되살릴 수 있습니다. **메신저·계정·비밀값은 못 되살립니다.**

1. `schema.sql`(우리 코드)을 먼저 돌립니다
2. **로그인 계정을 손으로 만듭니다** — `employees.id` 와 **같은 uuid** 여야 합니다.
   Authentication 화면에서는 uuid 를 못 정하므로 SQL 로 넣어야 합니다.
   **혼자 하지 말고 담당에게 요청하세요.**
3. 관리 → 되돌리기 → 꾸러미 열기 → 검사 통과 → 「되돌리기 SQL 만들기」
4. 내려받은 `.sql` 을 **읽어 본 뒤** SQL Editor 에서 돌립니다

> 이 길은 **반쪽입니다.** 전체 dump 를 받아 두는 편이 훨씬 낫습니다.

## 6. 비밀값과 비밀번호

### 로그인 비밀번호 — **전체 dump 가 있으면 그대로 삽니다**

`auth` 스키마에는 비밀번호가 **해시**로 들어 있고, dump 로 옮기면 **그대로 옮겨집니다.**
직원들이 쓰던 비밀번호를 **그대로 쓸 수 있습니다** — 새로 정할 필요가 없습니다.

> 평문 비밀번호는 **아무도, 어디에서도 볼 수 없습니다**(해시만 저장합니다).
> '못 본다'와 '못 옮긴다'는 다릅니다. **옮기는 것은 됩니다.**
>
> 2번 꾸러미만 있을 때는 계정 자체가 없으므로 새로 만들고 새 비밀번호를 정해야 합니다.

### 그 밖의 비밀값

전체 dump 에는 **들어 있습니다**(그래서 암호화가 필수). 2번 꾸러미에는 **안 넣습니다.**

| 무엇 | 보관 위치 (이름만) | dump 없이 되살리려면 |
|---|---|---|
| 알림 비밀키 | DB `push_config.secret` + Cloudflare 환경변수 | 새 값을 만들어 **양쪽에 같게** |
| VAPID 열쇠 | Cloudflare 환경변수 | 새로 만들면 **직원들이 알림을 다시 켜야** 합니다 |
| 직원 메일 비밀번호 | DB `user_mail.secret`(암호문) | **못 되살립니다.** 직원이 각자 다시 넣습니다 |
| 메일 암호 열쇠 | Cloudflare 환경변수 `MAIL_KEY` | 없으면 암호문을 못 풉니다. **따로 보관하세요** |

> 🔴 이 문서에도, 채팅에도, 인수인계 문서에도 **값 자체는 적지 않습니다.**
> 어디에 있는지와 이름만 적습니다.

## 9. 어디까지 됐나 — **코드와 실제는 다릅니다**

### ✅ 준비된 것 (시험까지 끝남)

| 무엇 | 어떻게 확인했나 |
|---|---|
| 업무 자료 꾸러미 만들기·검사·되돌리기 SQL | 시험 119가지 |
| 파일 목록 만들기·해시까지 맞추기 | 시험 34가지 (가짜 파일 2100개로) |
| 코드와 운영 구조가 어긋나는지 보기 | 시험 10가지 |
| 화면(관리 → 업무 자료 내보내기) | 빌드 통과. **배포는 안 했습니다** |
| 보관할 자리와 그 권한 | 0-1 — 대표님·지은님 둘뿐임을 확인 |
| 되살릴 자리를 잘못 짚지 않게 막는 문지기 | 시험 28가지 (`scripts/restore-guard.mjs`) |
| 이 문서의 절차 | 공식 문서를 따라 적음 |

### ❌ 아직 **한 번도 안 한 것**

| 무엇 | 왜 중요한가 |
|---|---|
| **실제로 백업을 받아 본 적이 없다** | 명령이 이 환경에서 도는지 아직 모릅니다 |
| **실제로 되살려 본 적이 없다** | **가장 큰 미검증.** 빈 서버에 부어 봐야 압니다 → `RESTORE-DRILL.md` |
| dump 명령을 이 컴퓨터에서 돌려 본 적이 없다 | CLI 가 아직 없습니다. 공식 문서가 바뀐 곳도 셋 있습니다(1번) |
| 받은 것을 보관 자리에 올려 본 적이 없다 | 폴더는 지금 비어 있습니다 |
| 기록 표(`backup_log`) | SQL 을 아직 안 돌렸습니다 |

> **"코드가 준비됐다"와 "백업이 된다"는 다릅니다.**
> 지금은 앞쪽까지입니다. 10번의 셋을 정하고 1·2·3번을 한 번 돌려야 뒤쪽이 됩니다.

### 그 밖에 안 되는 것

- **메일 진행 위치를 맞추는 방법이 없습니다.** 사서함마다 다르고 메일 서버에
  물어봐야 알 수 있어, 자동으로 맞출 수 없습니다(7번).
- **자동 백업이 없습니다.** 사람이 매달 명령을 쳐야 합니다.
- **파일 본체·암호화는 손으로 합니다.**
- `★지피티문서` 쪽 권한이 바뀌면 보관 폴더도 따라 바뀝니다. **가끔 다시 보세요.**

## 10. 실제로 돌리기 전에 — 실무 준비 세 가지

> **코드는 준비됐습니다. 실제 백업과 복구는 아직 한 번도 안 했습니다.**
> 아래 셋을 정해야 시작할 수 있습니다.

### ① 도구 — 무엇을 어디에 까나

| 무엇 | 어떻게 | 비용 | 쓰는 데 |
|---|---|---|---|
| **Supabase CLI** | 이 저장소에 `npm i --save-dev supabase@<판 고정>`(권장)<br>또는 Scoop | 없음 | dump 받기(1번) |
| **psql** | PostgreSQL 클라이언트만 설치 | 없음 | 되살리기(5번). **대시보드 SQL Editor 로는 못 합니다** |
| **7-Zip** | 설치 | 없음 | 암호화(②) |
| **Node** | 이미 있습니다 | 없음 | 파일 맞추기(3번) |

> CLI 는 **판을 고정**해 두세요. 고정하지 않으면 나중에 옵션이 바뀌어 같은 명령이 안 돕니다.

### ② 암호와 임시 평문 — 어디서 다루고 어디에 두나

**🔴 평문을 다루는 자리 — Dropbox 밖이어야 합니다**

```
C:\viren-backup-작업\   (예 — 동기화되지 않는 자리)
```

> **Dropbox 폴더 안에서 dump 를 받지 마세요.** `data.sql` 이 만들어지는
> **그 순간 동기화가 시작됩니다.** 암호화 전 평문이 클라우드로 올라가고,
> 지워도 **버전 기록에 남습니다.**

**차례**

1. **Dropbox 밖**에서 dump 를 받습니다
2. `7z a -p -mhe=on` 으로 묶습니다
3. `7z t -p` 로 **열리는지 확인**합니다
4. 확인된 뒤에 평문 `.sql` 을 지웁니다
5. **묶음만** 0-1 자리에 올립니다

**암호를 어디에 두나**

- 회사 **비밀번호 관리함**에 둡니다.
- 채팅·메일·메모장·파일 이름에 적지 않습니다.
- **대표님과 지은님이 각자** 가지고 있는 편이 안전합니다 — 한쪽이 잃어도 열립니다.
- 잃으면 **묶음을 영영 못 엽니다.** 백업이 있어도 쓸 수 없게 됩니다.

### ③ 격리 시험 환경 — 복구를 어디서 연습하나

> 🔴 **운영(`viren-work`)에서 연습하지 마세요.**
> 🔴 **Supabase 무료 프로젝트 둘(`viren` · `viren-work`)이 이미 차 있습니다.**
> 하나 더 만드는 것이 공짜라고 **단정하지 마세요.**

| 선택지 | 비용 | 할 수 있는 것 | 못 하는 것 |
|---|---|---|---|
| **A. 내 컴퓨터에 띄우기**<br>`supabase start`(Docker) | 🔴 **Docker 라이선스 확인 필요**<br>(직원 250명 미만 **그리고** 매출 1천만 달러 미만이면 무료) | roles·schema·data 복구, `psql` 차례, 방아쇠 끄기, 건수·권한 확인 | Storage·메일·알림은 실제와 다릅니다.<br>**Docker·WSL 설치 + 재부팅** 필요 |
| **B. Supabase 새 프로젝트** | **확인 필요** — 무료 두 개가 찼습니다 | 실제와 가장 가까움 | **돈이 들 수 있습니다. 승인 사항** |
| **C. 다른 Postgres** | 없음 | SQL 문법 확인 정도 | `auth`·`storage` 스키마가 없어 **제대로 된 시험이 안 됩니다** |

**권하는 길: A 부터.** 복구 차례의 대부분(5번 ②~③)을 그대로 밟아 볼 수 있습니다.
다만 **Docker 가 공짜인지부터** 봐야 합니다 — 회사 규모가 위 조건을 넘으면 유료 구독입니다
(https://docs.docker.com/subscription-billing/desktop-license/).
A 로 통과한 뒤에도 못 본 것(Storage·알림)이 남으면, 그때 B 를 **비용을 확인하고** 지은님께 올리세요.

> 어느 쪽이든 **Cloudflare Functions·cron 과 잇지 않습니다.** 이으면 연습하는 동안
> 직원들에게 알림이 나갑니다(5번 ①).
