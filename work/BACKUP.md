# 바이렌워크 — 백업과 되살리기

> 2026-11-05 작성. 무료 Supabase 에는 **자동 백업이 없습니다.** 직접 받아 두지 않으면
> 서버가 날아갔을 때 되살릴 방법이 없습니다.

---

## 0. 먼저 알아야 할 것 — 자료가 **네 군데**에 나뉘어 있습니다

| 어디 | 무엇 | 브라우저(관리 화면)로 받나 |
|---|---|---|
| **DB 표 21개** | 직원·인사·결재·근태·일정·메신저 | 13개만 ✅ · 메신저 3개 ❌ · 비밀 설정 ❌ |
| **저장소 3곳** | 결재 첨부, 대화 사진, 직인 | **경로·크기만** ✅ · 본체 ❌ |
| **로그인 계정** | 이메일·비밀번호 (Supabase `auth`) | ❌ 꺼낼 수 없음 |
| **비밀값** | 메일 비밀번호(암호문)·알림 비밀키 | ❌ 일부러 막아 둠 |

**관리 화면의 「업무 자료 내보내기」 하나로는 회사를 되살릴 수 없습니다.**
아래 1~3을 다 해야 전체가 됩니다.

---

## 1. 매달 — 업무 자료 내려받기 (5분)

**관리 → 기타 설정 → 업무 자료 내보내기 → 「업무 자료 내려받기」**

- 직원·인사 기록·경력·자격증·결재 문서·결재선·참조자·첨부 정보·근태·일정·양식·설정 **13개 표**
- 파일은 **경로와 크기만** 들어갑니다 (본체는 2번에서)
- 받은 뒤 화면에 나오는 **표별 건수**를 눈으로 확인하세요
- 회사 드롭박스 `VIREN_경영/백업/` 에 올립니다

> 한 표라도 못 읽으면 **파일이 아예 안 만들어집니다.** 반쪽짜리를 "다 받았다"고
> 내주지 않기 위해서입니다. 오류가 나면 그 내용을 그대로 담당에게 알려주세요.

---

## 2. 매달 — 메신저와 파일 (Supabase 대시보드)

### 2-1. 메신저 3개 표

브라우저로는 못 받습니다. **방에 들어가 있는 사람만 읽을 수 있게** 막혀 있고,
대표님도 예외가 아니기 때문입니다. (이 막음은 일부러 둔 것이고 풀지 않습니다)

**Supabase → SQL Editor** 에서 아래를 돌리고, 결과 오른쪽 위 **Download CSV** 를 누릅니다.
SQL Editor 는 관리자 권한으로 돌기 때문에 **전체가 나옵니다.**

```sql
-- ① 대화방
select * from public.rooms order by created_at;
```

```sql
-- ② 방 참여자
select * from public.room_members order by room_id, user_id;
```

```sql
-- ③ 대화 글
select * from public.messages order by room_id, created_at;
```

### 2-2. 파일 본체

**Supabase → Storage** 에서 폴더별로 내려받습니다. **세 곳 모두** 받아야 합니다.

| 저장소 | 무엇 | 지워지나 |
|---|---|---|
| `approval-files` | 결재 첨부 | **안 지웁니다** (근거 문서) |
| `chat-files` | 대화에 붙인 사진·파일 | 60일 뒤 자동 삭제 |
| `company` | **직인** | 안 지웁니다 |

> 1번에서 받은 꾸러미의 `files` 와 개수를 맞춰 보면 빠진 게 있는지 알 수 있습니다.

## 3. 일 년에 한 번 — 구조까지 통째로 (더 제대로)

표 구조·함수·방아쇠·권한(RLS)은 **우리 코드**에 있습니다 (`supabase/schema.sql`).
깃허브에 있으니 따로 받을 필요는 없습니다. 다만 운영 DB 와 어긋났을 수 있으니
일 년에 한 번은 통째로 떠 두는 편이 안전합니다.

```bash
npx supabase db dump --db-url "<Supabase → Settings → Database → Connection string>" -f viren-work-구조.sql
```

> 비밀번호가 든 주소입니다. **채팅이나 메일에 붙여넣지 마세요.**

## 4. 되살리는 순서 — 이 차례를 지켜야 합니다

서버를 새로 만들었다고 할 때:

### ① 구조 먼저
`supabase/schema.sql` 을 SQL Editor 에 통째로 붙여넣고 Run.
표·함수·권한이 만들어집니다. **자료는 아직 없습니다.**

### ② 로그인 계정 — 자료보다 **먼저**
**Supabase → Authentication → Users** 에서 직원 계정을 만듭니다.

⚠️ **직원 줄은 계정 번호(uuid)를 가리킵니다.** 계정이 없으면 직원 자료가 안 들어갑니다.
백업 꾸러미의 `tables.employees[].id` 와 **같은 uuid** 로 만들어야 합니다.
Authentication 화면에서는 uuid 를 정할 수 없으므로, SQL Editor 에서 넣어야 합니다 —
이 부분은 담당에게 요청하세요. **혼자 하지 마세요.**

### ③ 업무 자료
**관리 → 기타 설정 → 되돌리기 → 「꾸러미 열기」**

1. 꾸러미가 성한지 **검사**합니다 (건수·해시)
2. 무엇이 몇 건 들어가는지 **미리 봅니다**
3. 「되돌리기 SQL 만들기」 → 내려받은 `.sql` 을 **열어서 읽어 본 뒤** SQL Editor 에 붙여넣기

> 이 SQL 은 **한 덩어리로** 돕니다. 중간에 하나라도 걸리면 아무것도 안 들어간 채
> 되돌아갑니다. 반쪽으로 남지 않습니다.
> 다만 **같은 번호의 줄은 덮어씁니다.** 돌리기 전에 지금 자료를 먼저 받아 두세요.

### ④ 메신저
2-1 에서 받은 CSV 를 **rooms → room_members → messages 차례로** 넣습니다.
(가리키는 쪽이 먼저여야 합니다)

### ⑤ 파일
2-2 에서 받은 파일을 같은 경로로 올립니다. **경로가 다르면 첨부가 안 열립니다.**

### ⑥ 비밀값 — 다시 넣습니다 (5번 참고)

## 5. 비밀값은 백업하지 않습니다 — 다시 넣습니다

**일부러 뺀 것입니다.** 비밀번호나 열쇠가 일반 JSON 파일에 섞여 드롭박스를 돌아다니면,
파일 하나가 새는 순간 회사 메일함까지 열립니다.

| 무엇 | 어디에 | 어떻게 되살리나 |
|---|---|---|
| `push_config.secret` | DB (브라우저에서 못 읽음) | 새 값을 만들어 **Cloudflare 환경변수와 DB 양쪽**에 같게 넣습니다 |
| `push_config.url` 등 | DB | 새 서버 주소로 다시 넣습니다 |
| **VAPID 열쇠** | Cloudflare 환경변수 | 새로 만들면 **직원들이 알림을 다시 켜야 합니다** |
| `user_mail.secret` | DB (암호문) | 되살릴 수 없습니다. **직원이 각자 메일 비밀번호를 다시 넣습니다** |
| `MAIL_KEY` | Cloudflare 환경변수 | 이게 없으면 암호문을 못 풉니다. 따로 안전하게 보관하세요 |

> `user_mail.secret` 은 암호문이고 푸는 열쇠는 Cloudflare 에만 있습니다.
> **둘 다 있어야** 열립니다. 백업에 넣지 않는 이유이자, 넣어도 쓸모가 없는 이유입니다.

## 6. 되살릴 때 터지는 부작용 — 미리 막으세요

### ⚠️ 메일이 한꺼번에 다시 옵니다
`mail_state` · `user_mail.last_uid` 는 **"어디까지 봤는지"** 입니다.
과거 값으로 되돌리면 그 뒤에 온 메일을 **전부 새 메일로 보고** 알림을 쏟아냅니다.

→ **백업에 넣지 않습니다.** 새 서버에서는 지금부터 다시 세면 됩니다.

### ⚠️ 알림이 엉뚱한 기기로 갑니다
`push_subs` 는 기기 등록입니다. 옛 등록을 되살리면 이미 지운 앱으로 계속 쏩니다.

→ **백업에 넣지 않습니다.** 직원들이 '내 정보 → 기기 알림'에서 다시 켭니다.

### ⚠️ 되살리는 동안 알림이 터집니다
자료를 넣으면 방아쇠가 돌아 알림이 나갑니다.

→ 되살리기 **전에** `push_config.url` 을 비워 두고, 다 끝난 뒤 다시 넣으세요.

```sql
-- 되살리기 전
update public.push_config set url = null where id = 1;
-- 다 끝난 뒤 (주소는 새 서버 것으로)
update public.push_config set url = 'https://work.viren.kr/api/notify' where id = 1;
```

## 7. 지금 안 되는 것 (솔직하게)

- **자동 백업이 없습니다.** 사람이 매달 눌러야 합니다. 빠뜨리면 그만큼 날아갑니다.
- **되살리기를 실제로 해 본 적이 없습니다.** 코드와 SQL 은 시험했지만,
  빈 서버에 통째로 부어 본 적은 없습니다. 한 번 해 보는 게 가장 확실합니다.
- **로그인 계정은 손으로 만들어야 합니다.** 수가 적어 견딜 만하지만, 번거롭습니다.
- **파일이 많아지면** 저장소에서 내려받는 데 오래 걸립니다.
