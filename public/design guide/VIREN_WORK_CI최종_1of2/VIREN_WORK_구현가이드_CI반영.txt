이 문서는 기존 A확정 가이드를 보완합니다. 동봉된 20장 PNG는 CI를 참고한 디자인 시안입니다. 생성 이미지의 로고 형상·보호공간·색상을 정확한 원본으로 간주하지 마세요. 실제 구현에는 assets의 SVG와 아래 공식 CI 수치를 사용하세요. 이전 파일명 참조는 README의 최신 화면 목록으로 대조하세요.

1. 목표와 참고자료

승인된 홈 시안의 밝고 은은한 분위기를 홈·전자결재·근태·캘린더·메신저에 일관되게 적용합니다. 기능을 새로 만드는 프로젝트가 아니라 기존 업무 앱의 시각적 개선입니다.

시각적 기준:
- 승인 홈: VIREN_WORK_UI시안_3D없음.png
- 전자결재 확장: VIREN_WORK_전자결재_시안.png
- 근태 확정: VIREN_WORK_근태_A가로막대.png (사용자가 선택한 A안: 연속형 가로 막대)
- 캘린더 확장: VIREN_WORK_캘린더_시안.png
- 메신저 확장: VIREN_WORK_메신저_시안.png
- 기존 화면 참고: 사용자가 업로드한 순서대로 홈, 전자결재, 근태, 캘린더, 메신저의 5개 스크린샷.
- 함께 제공되는 나머지 4개 페이지 시안은 위 홈 방향을 확장한 제안입니다. 근태는 아래에서 확정한 A안 연속형 가로 막대와 하루 9시간 기준을 우선합니다. 이전 근태 시안보다 이 수정본이 우선하며 다른 화면과 기능의 범위는 바뀌지 않습니다.

원본 화면에서 확인한 기능과 승인 시안의 스타일을 구분합니다. 소스코드, 실제 CSS, 데이터 모델, 권한 정책을 검사한 문서는 아닙니다. 아래 치수·브레이크포인트와 UI 보조색은 구현 제안값이며 실제 CSS에서 추출한 값이 아닙니다. 공식 Yellow/Navy/Black은 CI PDF 지정값으로 별도 표시합니다. 이미지 속 이름·날짜·시간·건수·일정·대화 내용은 화면 참고용 스냅샷 또는 예시입니다. 운영 데이터로 하드코딩하지 않습니다.

2. 반드시 지킬 디자인 방향

- 아주 밝은 쿨 화이트 바탕에 라벤더·하늘색·크림빛이 살짝 비치는 배경.
- 주요 콘텐츠는 불투명한 흰 카드. 본문 뒤에 강한 그라데이션이나 블러를 깔지 않습니다.
- 노란색은 브랜드, 현재 메뉴, 핵심 버튼, 오늘 표시 등에 제한적으로 사용합니다.
- 보라·파랑·초록·분홍은 기능별 작은 아이콘 배경과 상태 표현에 사용합니다.
- 아이콘은 단정한 2D 선형 아이콘. 3D 아이콘, 인물 일러스트, 장식용 캐릭터, 대형 오브젝트를 넣지 않습니다.
- 여백, 명확한 숫자, 부드러운 카드 모서리로 품질을 만듭니다. 과도한 유리 효과나 두꺼운 그림자로 만들지 않습니다.
- 검정 상단 메뉴는 밝은 좌측 사이드바로 재구성하되 기존 메뉴·경로·로그아웃·관리 접근을 유지합니다.
- 읽기 편한 업무 도구가 우선입니다. 이미지와의 픽셀 일치보다 실제 정보의 가독성, 기능 보존, 반응형 동작을 우선합니다.

3. CI 적용 기준과 구현 토큰

공식 CI 기준 (18쪽 PDF의 표지 포함 페이지 기준, VIREN_CI_검토.txt에 정리된 검토 결과)
- p.11 공식색: Vivid Yellow #FBC825 / Solid Navy #00182C / Black #000000. 브랜드색은 이 지정값을 사용합니다.
- p.6~7: 로고는 제공된 공식 원본 에셋을 사용합니다. VIREN을 일반 텍스트로 타이핑하거나 새로 그려 대체하지 않습니다. 원본 에셋이 없으면 요청하고 임시 문자를 공식 로고라고 표시하지 않습니다.
- 가로 시그니처와 일체형 워드마크의 보호공간은 사방 로고 높이의 50%, 세로 시그니처는 사방 높이의 30%입니다. 비율·조합·내부 간격을 변경하지 않습니다.
- WORK는 제품명으로 분리하고 공식 로고 보호공간 밖에 배치합니다. 로고 주변은 깨끗한 흰 배경을 우선합니다.
- p.5 심벌 최소 높이는 화면 15px입니다. 이를 전체 로고 최소 폭으로 해석하지 않습니다.
- p.8~10: 원본 로고에 그림자·글로우·테두리·임의 윤곽선·왜곡·임의 색 변경을 적용하지 않습니다. 복잡하거나 대비가 낮은 배경을 피하고 지정된 배경별 조합을 사용합니다. 흰 바탕의 시그니처는 노란 심벌+검정 글자, 일체형 워드마크는 노랑입니다. 로고 규정을 일반 카드의 얕은 그림자 금지로 확대하지 않습니다.
- p.11 Gray 1~3는 RGB 표기와 HEX 표기가 불일치하므로 우선값을 CI 담당자에게 확인해야 합니다. 아래 UI 중립색은 공식 Gray를 재현했다고 주장하지 않는 잠정 제안입니다.
- p.13 Noto Sans는 명함 정보 영역에 지정되어 있습니다. 웹 전체의 필수 폰트로 확대 해석하지 않으며 기존 웹 폰트 유지 또는 Noto Sans 계열 검토가 가능합니다. 로고를 이 폰트로 재작성하지 않습니다.
- 연보라 배경은 공식 브랜드색이 아닌 승인된 UI 확장 제안입니다. PDF가 이를 명시적으로 허용하거나 금지했다고 단정하지 않습니다. 낮은 강도로 유지하되 로고 주변에서는 제거합니다. 엄격한 CI 적용이 필요하면 담당자 검수를 받습니다.
- 기능 상태색·외부 서비스 식별색도 UI 제안으로 구분합니다. 공식 CI 승인 완료라고 표현하지 않습니다.

배경 제안:
  기본 #F7F8FC 위에 넓은 radial-gradient를 2~3개만 중첩합니다.
  라벤더 rgba(222,215,255,0.38), 하늘색 rgba(221,237,255,0.32),
  크림 rgba(255,242,201,0.26)를 화면 모서리 중심으로 희미하게 사용합니다.
  배경은 정적 CSS로 처리합니다. 무한 애니메이션·대형 이미지 자산은 불필요합니다.

색상 사용 규칙:
- 브랜드 노랑은 #FBC825, 주요 제목·네비게이션은 #00182C를 사용합니다. tint·중립색·상태색은 공식 전용색이 아닌 UI 파생/확장 제안입니다.
- 노란 버튼의 글자는 진한 네이비. 노랑 위 흰 글자는 사용하지 않습니다.
- 연한 테두리는 장식용 구분에 한정합니다. 입력 경계·포커스·중요 상태는 더 선명한 별도 토큰을 씁니다.
- 캘린더 프로젝트 색상은 기존 분류 매핑을 유지합니다. 새 팔레트를 적용해도 프로젝트 의미가 바뀌지 않아야 합니다.
- 실제 조합별 대비를 검증합니다. 위 팔레트만으로 접근성 검증 완료를 주장하지 않습니다.

타이포그래피:
- 기존 한글 폰트를 우선 유지합니다. 필요하면 이미 설치된 Pretendard 또는 시스템 한글 sans-serif를 사용합니다. 새 폰트 패키지 추가는 별도 검토합니다.
- 페이지 제목: 데스크톱 30~32px / 줄높이 1.3 / 700.
- 모바일 페이지 제목: 24px / 1.35 / 700.
- 카드 제목: 18~20px / 1.4 / 650~700.
- 본문·버튼: 14~16px / 1.5 / 400~600.
- 캡션·표 보조값: 12~13px / 1.5. 주요 정보는 이 크기로 축소하지 않습니다.
- 홈 현재 시각: 데스크톱 56~64px, 모바일 40~48px / 1.1 / 700.
- 통계 숫자: 28~32px / 1.2 / 700. 단위는 14~16px.
- 시간·숫자는 tabular-nums 사용을 검토합니다. 한글 글자 간격을 과도하게 벌리지 않습니다.

공간·크기:
- 간격 스케일: 4, 8, 12, 16, 20, 24, 32, 40, 48px.
- 데스크톱 사이드바: 232~248px. 본문 바깥 패딩 32~40px.
- 카드 간격: 20~24px. 카드 내부 패딩: 24~28px, 모바일 16~20px.
- 카드 radius 20px, 작은 카드 16px, 입력·버튼 12px, 배지 999px.
- 그림자: 0 6px 24px rgba(24,35,70,0.04). 필요하면 1px 테두리 병용.
- 본문 최대폭은 약 1440px 제안. 근태·캘린더는 넓게, 문서 작성은 읽기 적절한 폭으로 조정합니다.

4. 공통 컴포넌트

사이드바
- 상단 공식 VIREN 로고 에셋과 보호공간 밖의 WORK 제품명, 중앙 홈/전자결재/근태/캘린더/메신저, 하단 관리/내 프로필.
- 활성 메뉴는 연한 노랑 배경, 진한 글자, 아이콘 색 강조. 색상 외에도 선택 형태와 aria-current로 구분합니다.
- 메뉴 높이 48~52px, 아이콘 20~22px, 라벨 15~16px.
- 관리 메뉴는 기존 권한 조건 그대로 렌더링합니다. 숨김만으로 권한을 대신하지 않습니다.
- 사용자 메뉴 안의 기존 내 정보·로그아웃 접근을 잃지 않습니다.

카드
- 흰 배경, 얕은 그림자, 여유 있는 패딩. 제목·보조동작·본문의 위치를 통일합니다.
- 요약 카드의 아이콘 타일은 약 48~56px. 아이콘은 기능을 설명하는 정도로만 사용합니다.
- 카드 전체 클릭과 내부 버튼이 중첩되면 잘못된 클릭이 생기지 않도록 구조를 분리합니다.

버튼
- Primary: 노랑 배경 + 네이비 텍스트. 페이지의 가장 중요한 동작에 사용합니다.
- Secondary: 흰 배경 + 테두리. Ghost: 배경 없이 보조 동작.
- Danger: 삭제·반려 등 실제 의미가 위험한 동작에만 사용합니다.
- 기본 높이 44px. 데스크톱 밀집 도구는 36~40px 가능하나 터치 환경에서는 44px 이상 확보합니다.
- hover/active/focus/disabled/loading 상태를 모두 정의합니다.
- 로딩 중 중복 제출을 막고 버튼 폭이 급격히 바뀌지 않게 합니다. 성공 이전에 완료된 것처럼 표시하지 않습니다.

입력·필터·탭
- 라벨은 필드 밖에 유지합니다. placeholder를 유일한 라벨로 쓰지 않습니다.
- 기본 높이 44px, 오류 설명은 해당 필드와 연결합니다.
- 검색·필터는 기존 구현이 있을 때만 스타일을 통일합니다. 시안에 보인다고 새 서버 쿼리나 검색 기능을 임의로 만들지 않습니다.
- 탭은 선택 상태·키보드 이동·초점 표시를 제공하고 기존 필터 의미와 상태 보존 동작을 유지합니다.

상태 표현
- 초기 로딩: 레이아웃 크기를 유지하는 skeleton 또는 기존 로딩 UI.
- 빈 결과: 선형 아이콘 + 짧은 설명. 실제 0건과 네트워크 실패를 구분합니다.
- 오류: 원인에 맞는 설명과 안전한 재시도. 오류를 0건으로 치환하지 않습니다.
- 권한 없음: 접근 불가 안내. 감춰진 데이터를 미리 로드해 클라이언트에 노출하지 않습니다.
- 데이터 없음/미기록/미출근/미래 날짜는 기존 의미대로 구분합니다.
- 데이터가 아직 없을 때는 ‘—’ 또는 기존 미기록 표현을 사용합니다. 임의의 0·100%·완료 상태로 채우지 않습니다.

5. 화면별 적용

5-1. 홈
구성 제안:
- 상단 날짜와 개인화 인사.
- 첫 행: ‘오늘의 근무’ 큰 카드 + ‘오늘의 일정’ 작은 카드.
- 둘째 행: 결재할 문서 / 진행 중인 내 문서 / 남은 연차 / 남은 대체휴무, 4개 요약 카드.
- 셋째 행: 결재함 + 바로가기 카드.

보존 사항:
- 출근·퇴근은 기존 핸들러, 서버 시각·근무 상태·확인 절차를 유지합니다.
- 근무 누적 시간 계산, 점심 포함 여부, 날짜 경계 등은 UI 변경으로 수정하지 않습니다.
- 결재함을 탭으로 묶더라도 ‘결재할 문서’, ‘내가 올린 문서’, ‘전체 보기’, ‘새 문서’ 접근을 모두 유지합니다.
- 연차 사용 설명·산정 기간·대체휴무 생성 조건 등 기존 보조정보를 시안이 간결하다는 이유로 삭제하지 않습니다.
- 바로가기의 실제 목적지와 기존 새 창 열기 정책을 유지합니다.
- ‘오늘의 일정’은 기존 캘린더 데이터를 재사용할 수 있는 경우에만 연결합니다. API 변경이 필요하면 별도 제안으로 분리합니다.
- 인사 이름·날짜·시간·수치를 시안 그대로 입력하지 않습니다.

5-2. 전자결재
구성 제안:
- 제목 ‘전자결재’, 우측 노란 ‘+ 새 문서’.
- 기존 5개 탭: 결재할 문서 / 내가 올린 문서 / 내가 결재한 문서 / 참조 문서 / 전체 문서.
- 흰색 큰 목록 카드. 데이터가 없으면 ‘문서가 없어요’와 작은 2D 문서 아이콘.
- 데이터가 있으면 기존 필드 기반 행 구성, 상태 배지, 제목 우선 정보 계층을 적용합니다.

보존 사항:
- 탭별 조회 범위, 결재선, 작성·승인·반려·참조 권한, 첨부파일, 문서 상태 전이를 그대로 유지합니다.
- 시안에만 존재하는 상태별 건수·검색·필터는 구현이 확인되지 않으면 새 기능으로 구분하고 기본 작업에서 제외합니다.
- 빈 상태에서 테스트 문서를 자동 생성하거나 승인 작업을 실행하지 않습니다.
- ‘전체 문서’라는 이름을 전 직원 데이터 공개로 해석하지 않습니다. 서버 권한이 우선입니다.

5-3. 근태 — A안 연속형 가로 막대 확정
사용자 추가 요구:
- 탄력적근무제를 사용하므로 정해진 근무시간을 다 채웠는지 도표로 확인하고 싶다는 요청입니다.
- 사용자는 A안이 더 보기 좋다고 선택했고 화면이 지저분해지지 않을지 우려했습니다. 따라서 연속형 가로 막대는 유지하되 날짜별 정보 밀도를 낮춥니다. 도넛이나 9칸 분절형 막대로 되돌리지 않습니다.
- 사용자가 확정한 기준: 하루 기준, 점심시간 1시간을 포함해 총 9시간(540분). 점심 60분을 다시 빼지 않습니다. 주간·월간 할당량은 이번 요구가 아닙니다.

구성 제안:
- 제목 + 월 선택 + 권한에 따른 직원 선택.
- 상단에는 오늘의 ‘실제 근무시간 / 9시간’, 높이 약 8px의 연속형 가로 막대, 남은 시간 또는 초과시간을 모아 보여줍니다. 오늘 날짜를 명시하고 월간 합계와 일일 기준을 혼합하지 않습니다. 선택일 상세는 별도 영역이나 팝오버에서 확인합니다.
- 기존 출근일 / 근무시간 합계 / 휴가(평일) 정보도 보존합니다.
- 달력/표 전환, 엑셀(CSV) 받기, 전 직원 CSV 버튼을 기존 제공 조건대로 배치합니다.
- 월간 달력은 흰 카드 안에 담고 옅은 구분선, 넉넉한 날짜 셀을 사용합니다.
- 기록이 있는 날짜 셀은 날짜 + 높이 4~6px의 가는 연속형 가로 막대 + 실제 근무시간을 기본으로 표시합니다. 필요한 날에만 작은 ‘10분 부족’ 또는 ‘10분 초과’ 문구를 추가합니다. 막대와 숫자는 같은 기록을 가리켜야 합니다.
- 날짜 셀 안에 출근·퇴근·퍼센트·범례를 모두 반복하지 않습니다. 출퇴근 시각과 퍼센트 등 세부정보는 별도 ‘상세’ 버튼으로 열리는 영역에 제공합니다. 상세 트리거는 터치·키보드로도 접근 가능하게 하고 hover에만 의존하지 않습니다.
- 막대는 옅은 중립 트랙과 차분한 단색 채움으로 표현합니다. 진행 중은 절제된 노랑, 충족은 차분한 초록을 기본 제안으로 하되 불필요하게 여러 색을 섞지 않습니다. 부족/초과는 작은 텍스트로 구분하며 모든 날짜에 배지나 빨간 경고를 붙이지 않습니다. 9개 구획, 칸별 테두리, 막대 내부 숫자, 도넛, 굵은 그림자는 쓰지 않습니다.
- 오늘은 노란 테두리·오늘 라벨로 표시합니다. 색상만으로 충족 여부를 전달하지 않습니다.
- 미래 날짜와 기록 없는 날짜에는 빈 막대를 반복하지 않습니다. 미기록을 0시간·미달로 단정하지 않습니다. 휴가·휴일·미기록·근무 중 상태를 구분합니다.
- 근무 비율이 100%를 넘으면 숫자와 ‘초과 ○시간 ○분’으로 명확히 표시합니다. 도형 트랙이 최대 100%여도 실제 값과 초과분을 숨기거나 잘라내지 않습니다.

보존 사항:
- 사용자가 확인한 ‘하루 9시간, 점심 1시간 포함’을 도표 기준으로 명시합니다. 기존 소스가 이와 다르게 계산하면 몰래 업무 로직을 덮어쓰지 말고 차이를 보고한 뒤 변경 범위를 확인합니다.
- 실제시간은 기존 출퇴근 기록을 사용합니다. 완료된 날은 출근부터 퇴근까지, 현재 근무 중인 날은 출근부터 현재까지의 기존 경과시간을 사용합니다. 과거에 퇴근 기록이 누락된 날을 현재 시각까지 계속 누적하지 않습니다.
- 도표 계산: 진행률 = 실제분 / 540 × 100, 남은분 = max(540 - 실제분, 0), 초과분 = max(실제분 - 540, 0). 표시 퍼센트는 정수 반올림 가능하나 시간과 충족 판정은 원래 정밀도를 유지합니다. 반올림 100%만으로 충족 판정을 내리지 않습니다.
- 계산 예시(검증용 스냅샷이며 운영 고정값 아님): 09:27~16:49는 7시간 22분=442분, 약 82%, 남은 98분=1시간 38분. 9시간은 100%, 8시간 50분은 약 98%·10분 부족, 9시간 10분은 약 102%·10분 초과입니다.
- 승인 휴가·휴일·다중 출퇴근·야간/자정 경계·기록 수정·별도 휴게시간 정책은 이 요청만으로 새 규칙을 만들지 않습니다. 기존 로직과 권한을 유지하고 불명확하면 확인 사항으로 남깁니다.
- 미기록은 0시간이나 결근으로 단정하지 않습니다. 일별 결과를 새로운 주간·월간 의무시간으로 환산하지 않습니다.
- 도표의 분자·분모·기준일·시간 단위를 명시하고 서버의 실제 데이터를 사용합니다. 예시 수치나 시안 속 비율을 운영값으로 쓰지 않습니다.
- 100%를 넘는 근무 비율도 임의로 100%로 잘라내지 않습니다.
- 기존 날짜 클릭은 출퇴근 시간 수정 동작으로 유지합니다. 날짜 클릭 핸들러를 상세 보기로 바꾸거나 가로채지 않습니다. 상세 정보는 별도 명시적 버튼/트리거로 열고 이벤트 전파를 분리하여 실수로 수정 동작이 실행되지 않게 합니다.
- 수정 권한, 기존 검증·이력, 휴일·휴가 처리, CSV 형식·인코딩·열 순서를 유지합니다.
- 관찰된 현재일 표시 차이: 홈은 근무 중 경과시간을 표시하지만 캘린더는 0%로 보였습니다. 원인은 아직 확인되지 않았으므로 데이터 오류나 특정 버그로 단정하지 않습니다. 기존 계산 흐름을 조사하고 홈의 근무 중 경과시간 표시 계산을 공통으로 재사용할 수 있는지 검토합니다. 표시를 맞추기 위해 출퇴근 기록을 새로 쓰거나 수정하지 않습니다. 동일 사용자·동일 날짜·동일 기준시각에서 두 화면의 숫자를 비교합니다.
- 근태를 ‘업무 성과 점수’처럼 새롭게 해석하지 않습니다.
- 월/직원 필터를 바꿨을 때 요약·달력·표·내보내기가 같은 범위를 가리키는지 확인합니다.

5-4. 캘린더
구성 제안:
- 상단 월 제목, 이전/다음, 오늘 버튼. 주요 본문은 큰 월간 달력 카드.
- 기존 프로젝트별 색상의 의미를 살려 저채도 이벤트 바와 선명한 텍스트 사용.
- 날짜 선택 시 기존 상세 영역을 아래 또는 넓은 화면의 우측 카드에 배치할 수 있습니다.
- 프로젝트 범례·선택일 일정·‘이 날 일정’ 추가 동작을 유지합니다.

보존 사항:
- 빈 날짜 클릭으로 새 일정, 일정 클릭으로 수정하는 기존 동작과 권한을 유지합니다.
- 여러 날 일정의 시작·끝, 주 경계 연결, 겹침, 월 경계, 종일/시간 일정, 시간대를 임의 변경하지 않습니다.
- 이벤트가 넘치면 ‘+N개’처럼 접근 가능한 펼침을 제공하되 기존 동작이 없으면 별도 UI 보완으로 검토합니다. 숨긴 일정이 영구적으로 접근 불가능해지면 안 됩니다.
- 색 외에 프로젝트 이름·범례로 식별할 수 있어야 합니다.
- 날짜 데이터와 요일은 실제 캘린더 로직으로 렌더링합니다. 생성 시안의 날짜 배치를 복사하지 않습니다.
- 생성된 캘린더 시안에는 월중 일정 구간이 생략되거나 서로 다른 막대가 합쳐져 보일 수 있습니다. 이미지의 길이·겹침·시작일·종료일을 정답으로 삼지 말고 실제 일정 데이터와 기존 배치 로직을 기준으로 구현합니다.

5-5. 메신저
구성 제안:
- 제목 ‘메신저’, 노란 ‘+ 새 대화’.
- 대화 목록은 흰 카드, 파스텔 원형 이니셜/그룹 아이콘, 대화명·최근 내용·시간의 계층.
- ‘바로 대화 걸기’ 기존 구성원 목록은 별도 작은 카드.
- 실제 상세 화면이 있다면 기존 구조를 보존하며 같은 색·간격·모서리 규칙 적용.

보존 사항:
- 기존 목록/상세 라우트와 새 대화 생성 흐름을 우선 유지합니다. 시각 개선만을 위해 새 3열 채팅 시스템을 만들지 않습니다.
- 대화 참여자 권한, 메시지 저장·정렬·읽음 처리·실시간 구독·알림 설정·전송 재시도를 변경하지 않습니다.
- 읽지 않은 메시지 수, 온라인 상태, 입력 중, 첨부, 검색은 실제 기능이 있을 때만 표시합니다.
- 본문에 존재하던 ‘대화 내용은 앱 안에 남으며 알림은 내 정보에서 설정’ 안내와 설정 접근을 유지합니다.
- 실제 전송이 필요한 QA는 승인된 테스트 환경·계정에서만 합니다. 디자인 검증을 위해 실사용자에게 테스트 메시지를 보내지 않습니다.

6. 반응형 제안

- 1200px 이상: 전체 사이드바, 홈 2열 주요 카드 + 4열 요약.
- 768~1199px: 본문 패딩 24px, 요약 2열. 공간이 부족하면 사이드바를 축소하거나 드로어로 전환.
- 767px 이하: 16px 패딩, 상단 메뉴 버튼 + 드로어, 카드 1열. 요약은 2열로 두되 긴 숫자/텍스트가 넘치면 1열.
- 드로어는 닫기 버튼, Esc, 포커스 관리, 배경 스크롤 잠금, 닫은 뒤 초점 복원을 지원합니다.
- 모바일 월간 달력은 정보를 축소해 숨기지 않습니다. 기존 표 보기·선택일 상세를 우선 활용하고, 가로 스크롤이 불가피하면 해당 영역만 스크롤합니다.
- 복잡한 표는 열을 임의 삭제하지 말고 영역 스크롤 또는 의미가 동일한 카드형으로 제공합니다.
- 메신저 상세가 있는 경우 모바일에서는 목록과 상세를 차례로 보여주고 뒤로가기·스크롤 위치를 보존합니다.
- 360, 390, 768, 1024, 1440px에서 확인합니다. 200% 확대에서 핵심 기능이 겹치거나 잘리지 않아야 합니다.

7. 접근성·사용성 검증 기준

- 일반 텍스트 대비 4.5:1 이상, 큰 텍스트 3:1 이상을 목표로 실제 색 조합을 검사합니다.
- 중요한 UI 경계·상태 및 포커스는 주변과 3:1 이상 대비를 목표로 확인합니다.
- 전체 동작을 키보드로 사용할 수 있어야 하며 포커스가 카드나 fixed 영역 뒤에 가려지지 않아야 합니다.
- 의미에 맞는 button/link/input/table 구조를 사용합니다. 아이콘 버튼에 접근 가능한 이름을 제공합니다.
- 제목 순서, 폼 라벨, 오류 연결, 상태 변경 안내를 확인합니다.
- 색·아이콘만으로 상태를 전달하지 않습니다. ‘근무 중’, ‘반려’, ‘오늘’ 등 텍스트를 함께 씁니다.
- 실시간 시계는 매초 스크린리더로 읽히지 않게 합니다. 중요한 성공·실패만 적절히 안내합니다.
- 움직임은 120~180ms 정도의 짧은 전환만 사용하고 prefers-reduced-motion을 존중합니다.
- 대화·문서의 긴 제목, 긴 한글 이름, 큰 숫자, 0건·다수 건을 모두 확인합니다.

8. Claude Code 실행 순서

이 문서는 실행 명령이 아니라 인계용 초안입니다. 아래 작업은 사용자가 자신의 Claude Code 환경에 전달하고 작업을 승인한 뒤 진행합니다.

1단계: 읽기 전용 조사
- AGENTS.md 등 저장소 지침, git 상태, 기존 미커밋 변경을 확인합니다.
- 실제 프레임워크, 라우터, 스타일 방식, UI·아이콘 라이브러리, 패키지 매니저, 테스트 명령을 조사합니다.
- 다섯 페이지의 경로·컴포넌트·데이터 소스·권한 조건·공유 레이아웃을 정리합니다.
- 기존 스택을 유지합니다. React/Next.js/Tailwind 등 특정 도구를 사용 중이라고 가정하지 않습니다.
- API·DB·인증·배포 환경 변경 없이 가능한 범위를 먼저 제시합니다.

2단계: 공통 스타일과 홈
- 기존 스타일 방식에 맞게 색·간격·글꼴·radius 토큰을 정의합니다.
- 기존 전역 CSS를 무차별 덮어쓰지 말고 영향 범위를 좁힙니다.
- 사이드바·버튼·카드·상태 UI를 적용한 뒤 홈을 기준 화면으로 검토합니다.
- 관리·내 정보·로그아웃 등 공통 메뉴 회귀를 확인합니다.

3단계: 나머지 네 페이지
- 전자결재 → 근태 → 캘린더 → 메신저 순으로 작은 변경 단위 적용.
- 페이지마다 기존 동작과 데이터 표시를 비교하고 진행합니다.
- 구현이 확인되지 않은 시안 요소는 임의로 기능화하지 말고 미적용 이유와 별도 제안으로 기록합니다.

4단계: 검증과 인계
- 저장소의 기존 lint/typecheck/test/build를 가능한 범위에서 실행합니다.
- 사용 가능한 로컬/개발 환경에서 주요 화면의 모바일·데스크톱 스크린샷을 비교합니다.
- 서버 데이터 변경 없이 가능한 탐색·필터·표시 테스트를 먼저 수행합니다.
- 실제 결재·출퇴근·일정 저장·메시지 전송은 승인된 테스트 데이터와 환경이 있을 때만 확인합니다.
- 실행하지 못한 테스트를 통과한 것처럼 보고하지 않습니다.
- 변경 파일, 완료 범위, 검증 결과, 남은 문제, 되돌리는 방법을 보고합니다.
- 커밋·푸시·배포·프로덕션 설정 변경은 자동으로 실행하지 않습니다.

9. Claude Code에 붙여넣을 프롬프트

[프롬프트 시작]

기존 VIREN WORK 앱의 UI를 첨부한 승인 홈 시안과 4개 확장 시안, 이 디자인 가이드에 맞춰 개선해줘.

목표는 밝고 은은한 배경, 흰색 소프트 카드, 절제된 노랑 포인트, 기능별 파스텔 아이콘, 좌측 사이드바를 갖춘 일관된 업무 앱이야. 공식 브랜드색은 노랑 #FBC825, 네이비 #00182C, 검정 #000000을 사용해. VIREN은 공식 원본 로고 에셋을 쓰고 WORK는 보호공간 밖에 분리해. 가로 시그니처/워드마크는 사방 높이의 50%, 세로 시그니처는 30%를 비워줘. 로고에 그림자·테두리·변형을 넣지 마. 기존 PNG는 CI 정렬 전의 초안이므로 이미 CI를 준수한다고 가정하지 마. 3D 아이콘, 캐릭터, 일러스트, 과도한 유리 효과는 쓰지 마.

먼저 저장소 지침과 git 상태를 확인하고 실제 기술 스택, 다섯 페이지의 경로, 공통 컴포넌트, 데이터 연결, 권한 조건을 읽기 전용으로 조사해. 기존 프레임워크와 스타일 방식을 유지하고, 미커밋 작업을 덮어쓰지 마. 조사 후 수정할 파일과 단계별 계획을 짧게 알려줘.

수정 범위는 홈·전자결재·근태·캘린더·메신저의 표현 계층과 공통 레이아웃이야. 인증, 사용자/관리자 권한, API 계약, DB 스키마, 업무 로직, 근태 계산, 결재 상태 전이, 일정 기간 계산, 실시간 메시징, 외부 링크, 기존 데이터 연동과 동작을 바꾸지 마. 기존 관리·내 정보·로그아웃 경로도 유지해.

가이드의 공식 브랜드 3색은 CI 지정값이고, 나머지 UI 보조색·크기는 제안값이야. 공식 회색은 PDF의 RGB와 HEX가 달라 확인이 필요해. Noto Sans는 명함 지정일 뿐 웹 필수 폰트가 아니야. 연보라 배경과 흰 카드는 승인된 분위기로 유지하되 연보라를 공식색이라 부르지 마. 기존 스타일에서 추출된 값으로 취급하지 말고 실제 화면과 접근성을 확인하며 조정해. 이미지 속 숫자·날짜·이름·대화·일정은 하드코딩하지 말고 기존 실제 데이터를 사용해. 로딩·오류·권한 없음·실제 빈 상태를 구분하고, 데이터가 없다고 가짜 값으로 채우지 마. 테스트용 샘플은 운영과 분리하고 예시임을 표시해.

시안에만 있고 기존 앱에는 없는 검색·통계·온라인 상태·새 기능은 임의 구현하지 말고 별도 제안으로 남겨줘. 특히 홈의 오늘 일정은 기존 캘린더 데이터를 안전하게 재사용할 수 있는지 먼저 확인해. 시안에 생략된 기존 필드나 보조설명도 삭제하지 마.

근태는 탄력적근무제에서 하루 근무시간을 채웠는지 확인하는 목적이야. 기준은 하루 9시간=540분이며 점심 1시간을 포함하므로 점심시간을 다시 빼지 마. 사용자가 선택한 A안 연속형 가로 막대로 구현해. 날짜 셀은 4~6px의 가는 막대와 실제 근무시간만 기본으로 두고 필요한 경우 작은 부족/초과 시간만 덧붙여. 오늘 요약은 상단에 8px 막대와 실제/9시간, 남은/초과시간을 모아줘. 차분한 색과 옅은 트랙을 사용하고 도넛, 9칸 분절, 반복 배지, 막대 내부 숫자로 복잡하게 만들지 마. 출퇴근 시각과 퍼센트는 별도 상세 버튼에 제공하되 기존 날짜 클릭 수정 핸들러와 권한은 그대로 유지해. 상세 버튼의 이벤트가 수정 동작으로 전파되지 않도록 해. 기존 출퇴근 기록의 실제 경과시간을 사용하고 현재 근무 중인 날만 현재 시각까지 계산해. 진행률은 실제분/540×100, 남은분은 max(540-실제분,0), 초과분은 max(실제분-540,0)이야. 100% 초과 숫자는 자르지 말고, 반올림한 비율만으로 충족을 판정하지 마. 미래·미기록 날짜를 미달·결근·0시간으로 단정하거나 빈 막대를 반복하지 마. 주/월 할당량이나 야간·휴가·별도 휴게 정책은 임의로 만들지 마. 기존 계산과 확정 요구가 충돌하면 먼저 차이를 보고해. 홈의 근무 중 경과시간과 근태 캘린더의 현재일 0%가 다르게 보인 관찰이 있지만 원인은 아직 확인되지 않았어. 기존 표시 계산을 조사해 공통으로 재사용할 수 있는지 검토하고, 표시를 맞추기 위해 기록을 변경하지 마. 근태 이미지보다 이 확정 요구와 실제 기록을 우선해.

공통 토큰과 사이드바·카드·버튼을 먼저 정리하고 홈을 기준으로 만든 뒤 전자결재, 근태, 캘린더, 메신저 순서로 적용해. 각 단계의 변경을 작게 유지하고 회귀를 확인해. 새 의존성·대규모 리팩터링·백엔드 수정이 필요하면 실행 전 이유와 범위를 알려줘. 문서 끝의 구조 개선 후보는 미승인 참고사항이므로 이번 구현에 자동 포함하지 마. 스키마·업무 흐름·저장 방식 변경은 반드시 별도 승인을 받아야 해.

데스크톱과 모바일, 긴 텍스트, 0건/다수 건, 키보드 탐색, 대비, focus, disabled/loading/error 상태를 검증해. 저장소의 기존 검사 명령을 실행하고 실패 원인과 미실행 항목을 정확히 보고해. 실제 업무 기록을 만드는 출퇴근·결재·일정 저장·메시지 전송은 승인된 테스트 환경과 데이터에서만 검증해.

마지막에 변경 파일 목록, 화면별 완료 내용, 실행한 테스트와 결과, 남은 문제, 검토용 화면을 정리해줘. 커밋·푸시·배포·운영 환경 변경은 하지 마.

11. 읽기 전용 실화면 검토 메모 — 선택적 개선 후보, 아직 구현 승인 아님

확인 범위:
- 관리 화면의 6개 탭과 내 정보를 읽기 전용으로 검토했습니다.
- 문서 작성은 기본 양식 3개와 커스텀 양식 1개를 검토했습니다.
- 기존 메신저 대화 2개와 캘린더 새 일정/수정 모달을 검토했습니다.
- 기존 문서가 없어 문서 상세의 실제 내용/동작은 검증하지 못했습니다.
- 나머지 커스텀 양식 8개, 인사 증명서, 양식 편집기, 저장 성공·실패·오류 결과는 미검증입니다. 화면을 열어본 사실을 저장/권한/업무 흐름 검증 완료로 표현하지 않습니다.

선택적 개선 후보:
- 문서 작성: 결재자 선택 영역이 커서 본문을 밀어냅니다. 현재 선택된 결재선을 간단히 요약하고 필요할 때 편집하는 배치를 검토할 수 있습니다. 결재 순서·필수 인원·권한·전송 규칙은 그대로 유지하며 구조 변경은 별도 검토합니다.
- 캘린더: 새 일정/수정 모달의 기본 구성은 유지할 만합니다. 좁은 폭에서 긴 프로젝트명이 잘리지 않도록 줄바꿈·선택 영역 폭·전체 이름 확인 수단을 검토합니다. 일정 데이터나 저장 방식 변경 제안이 아닙니다.
- 메신저: 넓은 화면에서 대화 목록+선택 대화의 2열 배치를 선택적 개선으로 제안합니다. 기존 2개 대화를 확인했지만 라우트·읽음 처리·실시간 구독 변경은 승인되지 않았습니다. 기본 구현은 앞서 정한 기존 목록/상세 동작 보존입니다.
